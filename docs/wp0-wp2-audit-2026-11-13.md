## Defects fixed with high confidence

### Security and data integrity

1. **Authorization could evaluate to `NULL` and fail open.**
   The result-submit and checked-start RPCs combined a nullable `umpired_by` comparison with boolean predicates, then used `IF NOT v_authorized`. PostgreSQL treats `IF NOT NULL` as non-true, so an ordinary authenticated user could pass the guard. All WP1/WP2 consumers now require `v_authorized IS TRUE`, and `can_umpire_match` now returns explicit `false` with a safe `search_path` and restricted grants.
2. **Result and correction attribution could be spoofed.**
   Client-supplied `p_umpire_id` / `p_scored_by` could name another profile. Both RPCs now derive the actor from the authenticated identity and reject mismatched supplied IDs.
3. **Correction retries were not idempotent.**
   A lost response followed by retry could increment the revision and write another audit row. Correction operation IDs are now stable across UI retries, and the RPC returns `already_applied` for the same operation and payload.
4. **Unsafe winner changes could corrupt derived state.**
   The correction RPC does not reverse Elo or recompute team-tie outcomes. It now blocks winner changes for ranked tournaments and team ties, while still allowing score-only corrections. A coordinated recalculation belongs in WP7.
5. **Corrections were accepted for non-completed matches and malformed results.**
   The RPC now requires an accepted completed result, a non-empty score and at least one set.
6. **Bracket advancement referenced obsolete columns.**
   `20261019000008_fix_advance_tournament_winner.sql` uses non-existent `loser_advances_*` fields. A new additive migration restores the actual `advances_to_match_loser` / `advances_to_position_loser` fields and the partner-safe label behavior. The historical migration is left intact because it may already be recorded in deployed migration history.

### Offline recovery and accessibility

7. **Conflict resolution on a shared device could delete another umpire's snapshot.**
   Queue cleanup is now scoped by match and owner. A regression test covers two owners sharing one device.
8. **The conflict dialog did not manage focus.**
   It now focuses the correction reason or safe server-result action on open, traps keyboard tab navigation, supports Escape while idle and restores previous focus on close.
9. **Generated RPC typing was bypassed.**
   The correction function is represented in the generated database contract and the service no longer casts the RPC name to `any`.
10. **The concurrency harness could report false authorization success.**
    It previously caught its own assertion and used an already-completed match, so any rejection looked valid. It now uses a dedicated scheduled fixture, validates session claims, requires exact SQLSTATE/message pairs, tests both checked start and result submission, is repeatable, and accepts `TEST_DATABASE_URL`.
11. **The offline integration suite tested a fake queue rather than production behavior.**
    It now mounts `useOfflineUmpireSync` and exercises the real queue utilities through in-memory Capacitor Preferences/App adapters and a mocked final network boundary. Coverage includes coalescing, owner isolation, exact acknowledgement, failed retry, mid-flush replacement, reconnect, native resume and queue removal.

## Items requiring review or a product/deployment decision

### P0 — before staging or production deployment

1. **Representative schema rehearsal.** The checked-in historical chain still lacks a foundational `players` creation before an early migration references it. Run the additive WP1/WP2 migrations on an approved schema-only staging clone and retain the transcript. Do not rewrite old applied migrations.
2. **Old-client finalization policy — resolved locally.** `20261113190000` revokes both legacy result RPCs from client roles. Staging rollout must require the revisioned client version before applying it.
3. **Admin correction convergence — resolved locally.** First-party score completion uses v2; completed-result changes use the reasoned correction dialog; bracket repair uses `advance_tournament_winner`.
4. **Migration deployment and compatibility.** None of the audited migrations has been applied to the hosted project. Confirm migration order, generated types, rollback/forward-fix procedure and old-client behavior before authorization to deploy.

### P1 — required to close WP0/WP2 release evidence

5. **Replace the Playwright umpire test — partially closed.** Obsolete RPC interception, debug logging and fixed sleeps are gone; rapid scoring/correction and keyboard behavior pass. Browser/native reconnect, stale revision, lost-session and exact-once finalization remain release journeys.
6. **Decide live-score concurrency semantics.** In-progress tournament score writes still directly update `tournament_matches` and are last-writer-wins. Final results are protected, but two live officials can overwrite the displayed in-progress score. Either enforce one active scorer or add live-score revisions.
7. **Native recovery evidence.** The production hook integration suite covers the native adapter boundary, but it does not prove Android process death/resume, Preferences persistence or reconnect timing. Record one native recovery run before release.
8. **Regenerate Supabase types from the representative schema.** The local generated contract was updated carefully, but authoritative regeneration should follow staging migration verification.

### P2 — cleanup after the gates above

9. **Legacy queue ownership migration.** Old v1 umpire entries have no owner and are attributed to the signed-in user during upgrade. On a truly shared device that attribution cannot be proven; consider quarantining legacy ownerless entries instead.
10. **Test-only route exposure — resolved.** `/test-umpire-engine` is compiled into routing only when `import.meta.env.DEV` is true, with a static release-gate assertion.
11. **Performance baseline.** WP0 still lacks measured queue flush latency and conflict-dialog/load timing on a realistic tournament fixture. Do not invent budgets; measure first.
